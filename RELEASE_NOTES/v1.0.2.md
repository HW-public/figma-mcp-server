# figma-mcp-server v1.0.2

## 亮点

### 1. 多频道支持——每频道并行 FIFO、会话绑定、防串兜底

一个 broker 同时服务多个 Figma 窗口（多文档并行设计），互不阻塞：

- **每频道独立 FIFO**：频道 A 的大批量写入不再堵频道 B 的读写（head-of-line blocking 消除）；频道内保持串行，同一文档操作顺序有保证
- **会话绑定**：新增 `channel_list`（频道池+频道码→文档名映射+本会话绑定）与 `channel_use`（把会话绑定到已 join 频道）；绑定后调用不用记频道码，路由优先级：显式 `channel` 参数 > 会话绑定 > 默认频道；子 agent 共享父会话连接，绑定自动继承
- **防串兜底**：join 返回频道码→文档名映射（看清"哪个码是哪个文档"再写）；未 join 频道调用返回 `CHANNEL_NOT_JOINED` + 已加入列表；池非空但无绑定无默认时返回引导错误
- **持久化修正**：`channel_join` 的 `keepDefault` 参数——join 新码不再无条件篡改机器默认频道
- **插件频道码按文档名隔离**：clientStorage 跨窗口共享导致的双窗口撞码已修，每个文档稳定持有自己的频道码
- batch_execute 每个 op 可带 `channel`，一条批量跨两个窗口写

### 2. 崩溃自愈链补完——子进程 WS 死亡自动重建

- figma-edit-mcp 子进程 ↔ socket 桥 的 WS 断线后自动重建子进程（含 10 次重试、成功后自动重进频道），不再需要整 broker 重启
- socket 桥崩溃 2 秒自动重拉（EADDRINUSE 与正常关机智能不重拉）
- pid 文件改为抢端口成功后才写，并发唤醒不再留陈旧 pid

## 其他改进

- **broker 风暴读缓存**：9 个只读工具按"工具+规范化参数"缓存（TTL 1500ms，`FIGMA_MCP_READ_CACHE_TTL_MS` 可调），响应带 `fromCache`/`snapshotAgeMs` 回执；任何写成功即整表清空
- **审计日志**：参数截断改 160 字符头+尾双保留，create 类调用的 parentId/坐标等尾部关键参数不再被切掉；新增 `[ok-cache]` 命中标记
- **工具响应回执**：create_*/node_transform 响应 echo 实际生效的 `coordinateSpace`（canvas/parent）
- **工具 schema 对齐**：工具数 46 全量核对、README 配置表补审计/缓存 env、coordinateSpace 回执进 outputSchema
